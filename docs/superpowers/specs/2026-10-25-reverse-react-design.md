# ReverseReAct 最小闭环 · 设计说明

- 日期：2026-10-25
- 依据：`MungerMind_v0.2.md` 第 5 章「ReverseReAct 规格」
- 范围：只做「发送问题 → 使用 ReverseReAct 思考 → 返回答案」。不接工具、不做权限网关、不做推理模式调度器（第 6 章）、不做多智能体（第 7 章）。

## 意图

把一个逆向推理引擎跑通，供后续调度器与报告层调用。它必须自己拥有子策略选择、验证任务生成、循环控制和结构化结果协议（5.1），而不是散在提示词里。

## 目标

1. 一次调用可选择并执行 A / B / C 中的一种或多种子策略（5.2）。
2. 按 5.3 九步协议在每轮内完成：读上下文 → 选策略 → 生成逆向发现 → 转为验证任务 → 执行并观察 → 更新判断 → 判断继续或停止 → 输出结构化结果。
3. 每轮返回 5.5 节列出的 10 个字段，经 Pydantic 校验；无效模式名、无效证据引用、超出预算的行动不得进入执行。
4. 默认两轮，可配置默认轮次与硬性上限（5.4）。
5. `run(question)` 返回最终答案字符串；同时保留每轮结构化结果供审计。

## 非目标

- 工具调用与外部检索。没有工具可用时，必须明确标记「未做外部验证」（5.3 第 6 步），不伪造引用（8.3）。
- 用户暂停 / 恢复状态机。只实现「取消后不再发起任何模型调用」（10.3）。
- 置信度校准、多专家、证据分级。属于其他章节。

## 采用的方案

候选一：单文件 `mungermind/agents/reverse_react.py`，与既有 `simple` / `react` / `reflection` / `plan_solve` 四个范式并列，复用 `Agent` 基类与 `LLM.invoke`。
候选二：拆成 `mungermind/reasoning/reverse/` 包（models / strategies / engine + 适配层），为调度器和工具网关预留结构，但与现有 `reasoning/pipeline.py` 的五步固定流程耦合，且文件数翻倍。

选择候选一。理由：本次明确只要最小闭环；engine 逻辑集中在一个类里反而更容易在接入调度器时整体抽出。

## 每轮两次模型调用的理由

5.3 的九步不适合塞进一次调用：第 3–4 步（发现 → 验证任务）需要先形成逆向发现，第 6–8 步（观察 → 更新判断 → 停止判断）必须站在已有发现之上才有意义。因此：

- **分析调用**：选策略、给出当前立场、生成发现、验证问题、建议行动、决策影响、未解决事项。
- **复核调用**：逐条给发现打 `supported` / `challenged` / `unverified`，更新当前立场，重新评估是否继续。
- **汇总调用**：循环结束后把最终立场写成面向用户的答案。

第 6 步「执行并观察」在本版本没有工具，等价于「以推理复核」，并在结果与最终答案中标注未外部核验。

## 关键决策（我的判断，非用户指定）

| 决策 | 取值 | 理由 |
|---|---|---|
| 默认轮次 | 2 轮，且默认**不**追加 | 验收清单要求「ReverseReAct 默认最多执行两轮完整循环」；追加是配置行为，不是默认行为。 |
| 硬性循环上限默认值 | 3 | 5.4 允许临时值，并注明不得视为已确认的产品决策。写在常量与文档里。 |
| 追加循环 | `allow_extension=True` 时启用，需同时满足「模型建议继续 + 有未解决问题 + 有未出现过的新行动」 | 5.4 的继续条件为合取，缺一即停；关闭时第 3 轮起永不发生。 |
| 无效证据引用 | 用 `evidence_ids` 白名单过滤，被丢弃的引用记入 `dropped_evidence_refs` | 5.5「无效证据引用不得进入执行」；没有白名单时全部丢弃，避免伪造引用。 |
| 行动预算 | 每轮 `max_actions_per_cycle` 条，超出截断 | 5.5「超出预算的行动不得进入执行」。 |
| 用户指定子策略 | `strategies=(...)` 时以用户为准，模型建议的其他策略只在 `selection_reason` 里注明未采纳 | 3.1「用户手动配置不得被模型静默覆盖」。 |
| 结果标记 | `externally_verified` 恒为 `False` | 本引擎不调工具；保留字段供接入工具后改为真实结果。 |

## 留给后续

- 接入统一工具网关后，把「执行并观察」换成真实工具调用，并让 `externally_verified` 反映实际结果。
- 接入调度器（第 6 章）后，`strategies` 由规则引擎给出。
- 需要跨轮缓存已有发现时，可在 `_seen_actions` 之外增加发现去重。
